# 使用 ffmpeg-agent 处理媒体

把用户的媒体处理需求完成为可用的本地结果。技能目录包含独立 Python 3.10+ 标准库客户端，不需要服务端源码、Docker、FFmpeg 或模型 Key。

## 选择执行方式

读取用户指定的私有消费者配置，只使用服务地址和服务 Token。已连接原生 MCP 时，先通过 `tools/list` 与 `list_capabilities` 发现实际工具、参数和限额；否则运行 `scripts/media_client.py --env-file <私有配置> capabilities`。连接失败时按已安装的 `ffmpeg-agent-connect` 排查，或读取本技能的 [references/workflow.md](references/workflow.md#配置与调用)。不要擅自修改宿主或服务端配置。

- 用户目标可直接表达为受支持操作与参数时，通过原生 MCP 或结构化 HTTP 提交，无需服务端再调用模型。
- 用户明确委托服务端规划，或需要它规划组合任务时，先确认自然语言能力开启，再使用 `generate_media`、HTTP 自然语言入口或 A2A。尊重用户选择的协议；失败时不静默切换协议或再次请求模型。
- A2A 用于自然语言委托；结构化任务使用 HTTP/MCP。本服务使用远程 Streamable HTTP MCP，没有 stdio 入口。
- 通用默认优先保留源特征。省略 `params` 或只覆盖用户要求的字段；不要主动套用改变尺寸、帧率、声道的预设。操作、可用编码器与约束以当前部署返回的 schema 为准。

## 完成处理

先明确输入文件和输出位置。只上传用户选择的文件；本地路径不能作为远程输入。HTTP 上传返回 `file_id` 后才能在 MCP/A2A/HTTP 请求中引用。上传期间保持源文件不变，最多一次传入四个具名输入。

每次新任务使用新的私有状态文件和未存在的输出目录。原生 MCP 工作流用 `upload` 保存输入引用与稳定 `request_id`，以该 ID 作为幂等键提交，再用 `collect` 接手返回的 `job_id` 或 `agent_task_id`。没有原生协议工具时，用 `run` 完成全部流程。多步任务、自定义参数及完整命令见 [references/workflow.md](references/workflow.md)。

任务已接受、模型计划完成或 A2A 返回 Task 都不等于媒体完成。持续查询实际媒体任务；只在完成下载和大小/SHA-256 校验后把文件作为成功产物交付。

| 状态/情况 | 必要处理 |
| --- | --- |
| 等待超时、网络中断或提交结果不确定 | 保留原状态文件；CLI 提交用 `resume`，原生 MCP 提交用相同请求和幂等键恢复确认后 `collect`，不要重复上传或创建新请求 |
| `needs_input` | 根据原请求补问构造受支持任务所必需的信息；补充后使用新状态与新请求 |
| `unsupported` | 说明当前能力边界；用户改为支持范围内的需求后再用新请求提交 |
| `partial` | 下载可用结果，明确失败输出或集合成员；不能报告为全部成功 |
| `failed` | 报告稳定错误和已验证的结果；不盲目重试模型 |
| 取消 | 发出取消后继续查询，直到实际终态且 `inputs_released=true`；收到取消请求不是已停止 |

完成收集并确认输入不再使用后，仅 release 本次状态文件登记的托管上传。客户端在成功/部分成功且 `inputs_released=true` 后自动完成该步骤；失败、取消或未提交的上传按引用状态显式处理。不得 release 用户未授权的其他文件，不删除用户本地源文件，也不提前释放仍需继续下载或复用的产物。

状态文件含任务标识、文件引用和本地路径，应私有保存，不输出其全文。Token 不进入命令参数、聊天、日志或报告。下载不得覆盖已有文件。

交付时给出实际输出文件、媒体终态、校验结果，以及部分失败或未完成的项目。若仍在运行，说明如何用现有状态文件恢复，不能把等待超时报告为媒体失败。
