# 媒体服务首版实施计划

状态：实施基线，各阶段状态与验收证据见[实施进度](v1-implementation-progress.md)\
日期：2026-10-13\
目标仓库：`ffmpeg-agent`\
依据：[首版设计](../design/media-service-v1.md)与[技术选型](../design/technology-selection-v1.md)。

## 1. 首版交付目标

交付一个适用于内部部署的独立媒体服务 Docker 镜像，包含 HTTP API、SQLite 状态、调度器和可配置的容器内 Worker。不部署单独数据库服务，不依赖消息中间件，不建设历史任务库。

必须支持三种输入引用、六个版本化媒体操作、有限 DAG、部分成功、不可变产物、取消、重启恢复、租约与回收。同机通过共享卷交接，跨机通过 HTTP 获取和消费；两条路径遵循同一任务协议。

API 固定一个应用进程，`worker_concurrency` 默认 1、允许 1～4，分别控制并发任务槽和媒体子进程总数。一个任务内部串行执行步骤，媒体处理并行发生在不同任务之间。SQLite 保留恢复所需的活动状态和有限幂等信息，终态任务在不再承担引用/查询承诺后回收。

本计划不包含 MCP、语言 SDK、Web 界面、直接上传、分布式 Worker、GPU、HLS、NFS、高可用或业务资产管理。文件复制、样例生成、代码、锁文件、镜像及部署配置随对应阶段实现和验证；本文列出验收要求，不代替执行证据。

## 2. 阶段与依赖

| 阶段 | 交付结果 | 前置依赖 | 完成判断 |
| --- | --- | --- | --- |
| P0 契约与运行基线 | schema、预设、配置边界、镜像兼容结论、fixture 清单 | 当前设计与选型 | 没有影响实现的未定协议分支 |
| P1 单容器控制面 | 启动、认证、SQLite、持久接受、幂等、有界调度 | P0 | 接受即持久，重放一致，并发配置有效 |
| P2 文件与执行底座 | 安全共享文件读取、资源预算、进程组控制 | P1 | 真实子进程可执行、超时、停止并回收 |
| P3 最小业务闭环 | `media.probe.v1`、发布检查点、共享卷产物读取 | P2 | 从提交到可消费产物及重启核对完整可用 |
| P4 操作与组合 | 其余五个操作、DAG、部分成功 | P3 | 六操作和依赖规则通过真实素材验证 |
| P5 生命周期 | 取消、恢复、租约、保留、回收与元数据清理 | P3 | 无提前释放、无覆盖发布、无错误删除 |
| P6 HTTP 文件通路 | 受控获取、固定副本、流式访问与读取保护 | P4、P5 | 远端路径和断流收尾满足同一生命周期 |
| P7 集成与交付 | 故障验收、资源实测、部署示例、运维文档 | P6 | 验收矩阵有可复核证据，剩余限制明确 |

主路径为 `P0 → P1 → P2 → P3 → P4/P5 → P6 → P7`。P4 和 P5 可在共享状态/引用接口冻结后并行；P0 内的媒体兼容性验证与 schema 编写可并行。接口、数据库状态规则和最终集成由同一 owner 负责，不能各模块自行扩展公共语义。

## 3. 分阶段工作包

### P0：固定契约、预设和验证素材

工作内容：

- 固定创建任务、查询、步骤结果、产物、清单、租约、错误和 capabilities 的请求/响应 schema。拒绝未知字段和不支持版本，区分创建期 `4xx` 与执行期失败。
- 固定命名输入/输出和 DAG 规则，明确操作输入类型、必需端口、输出端口、无用途步骤拒绝、失败依赖跳过和部分输出如何传递。首版下游默认不消费部分成功结果；仅显式声明支持部分输入的操作例外。
- 定义同键请求规范化规则、配额计算范围、幂等保证到期字段、终态与 `inputs_released` 一致性、最小任务记录的清理条件。
- 固定集合分页接口 `/v1/artifacts/{artifact_id}/members`、成员顺序与逐项索引；重复抽帧时间点保留为独立请求项，不能用时间值作唯一键。
- 固定 HTTP GET/HEAD、单区间 Range、合法多区间回退完整 `200`、ETag/If-Range、租约头及 retiring 状态下的可读取范围。
- 固定 UTC 时间和媒体时间归一化：起始 PTS、旋转、SAR、帧间请求、重复/无序时间点、缺失或非单调 PTS 的处理，以及各时间字段的精度。
- 验证并冻结 H.264/AAC/PCM 预设、静态图片 contain/cover、放大规则、透明转 JPEG、EXIF 方向和颜色空间限制；明确 HDR 等未支持输入的拒绝方式。
- 验证 Python 3.14、FastAPI/Pydantic、Pillow、aiosqlite 与 FFmpeg 7.1 系列在目标架构的安装和基本能力，确定精确版本、镜像 digest、系统包清单与 uv.lock。amd64、arm64 各自需要真实结果。
- 做安全 FD 传递和 FFmpeg 输入格式/协议限制原型；确认校验与实际读取之间无路径替换窗口。若受选定引擎版本约束，先形成可验收替代方案再进入 P2。
- 按第 4 节复制基础 fixture，建立来源、用途、大小、SHA-256 和合成命令说明；补充小型确定性边界媒体生成方式。

交付物：版本化 OpenAPI/schema、错误码目录、预设说明、配置说明、依赖锁与构建基线、fixture README 和测试分层约定。具体目录在建仓时按职责划分，不要求先生成空模块骨架。

验收：示例任务可按 schema 校验；非法 DAG、未知字段和不支持媒体组合有明确结果；预设能够处理对应基础 fixture；镜像与真实引擎报告可复核。P0 验证只证明基线可用，不代表已交付服务。

### P1：单容器 API、SQLite 与可配置 Worker

工作内容：

- 建立应用生命周期、单实例文件锁、配置校验、认证与调用方作用域、健康及就绪接口。禁止 Uvicorn 多进程和 reload；Worker 数量从同一配置模型读取。
- 建立私有 SQLite 状态目录、编号迁移和 schema 版本检查。单 aiosqlite 连接，DELETE journal、FULL 同步、外键、有限 busy timeout；不引入独立数据库或队列服务。
- 封装唯一事务入口，应用锁覆盖所有读写、取回结果、提交和回滚。取消时必须确认事务退出后才释放锁，不把 HTTP/文件/进程 I/O 放入事务。
- 实现任务、步骤、尝试、幂等、产物、引用、租约及发布状态所需的最小表与索引；用唯一约束和条件更新保护身份范围及状态转换。
- 实现 capabilities、任务创建/查询，以及创建事务中的配额校验、幂等判定和已有产物引用获取。提交后才响应 `202`。
- 实现一个持久队列扫描调度器，按 `worker_concurrency` 领取任务。内存事件只负责唤醒；槽位释放覆盖成功、失败、异常和取消。此阶段可使用测试执行器验证调度，不能声称媒体处理已完成。
- 开始记录有限结构化日志，遮蔽凭据、签名 URL 和敏感路径；进度合并写入，状态关键点立即持久化。

验收：

- 同一调用方并发提交相同 key，仅一个任务；相同 key 不同请求返回 `409`，不同调用方互不冲突。
- 接受成功后立即重启，任务仍可查询；持久化失败、队列满不会返回接受成功。
- 1、2、4 个 Worker 的运行槽数量准确，超出范围启动失败；第二应用实例不能打开同一状态目录工作。
- 随机取消数据库协程后，无跨事务读写、未完成回滚或连接长期占用；没有网络和媒体操作持有事务锁。

### P2：共享文件访问、执行器与资源边界

工作内容：

- 实现 `storage_id/key` 映射、调用方授权和稳定的普通文件访问；拒绝绝对路径、`..`、符号链接、设备、FIFO 和目录。源文件借用只读，服务无权删除。
- 建立每任务/每尝试私有工作目录，登记归属。限制输入大小、时长、像素、步骤数、输出量和临时空间，保留磁盘安全余量。
- 大文件复制、摘要、同步落盘和删除采用有界线程执行与分块取消检查，不阻塞事件循环；取消后等待实际文件操作完成并关闭句柄，不能把取消线程等待者当成文件工作已停止。
- 实现统一子进程执行器：无 shell、独立进程组、stdout/stderr 消费、输出截断、超时、TERM/KILL、wait/reap，以及关闭期间的执行停止。
- 对 ffprobe、FFmpeg 与 Pillow 辅助进程统一计入任务槽。一个任务任一时刻最多一个媒体子进程，不因多个 DAG 分支突破全局上限。
- 实现任务全程预算和剩余预算传递；排队超时也需要完成状态收尾。重试次数、超时和线程预算由部署配置提供。

验收：真实 ffprobe 与 FFmpeg 可处理基础样例；恶意路径和媒体外部引用被拒绝；stderr 持续输出不堵塞；忽略 TERM 的测试子进程最终被 KILL 并回收；API 在两个媒体子进程工作时仍能查询，执行器取消可独立验证，HTTP 取消全链路在 P5 验收。停止确认之前不得提交 `inputs_released=true`。

### P3：probe 到不可变产物的完整闭环

工作内容：

- 实现 `media.probe.v1`、规范化报告、缺失字段处理和公共错误映射。
- 实现产物 ID、不可覆盖 key、file/collection 基础模型、共享位置授权以及元数据查询。
- 建立发布意图、完整性校验、输出区暂存、同步和重命名、ready 提交及步骤检查点。文件系统操作在事务外，前后核对有效尝试和取消意图。
- 实现发布中断后的核对：文件未生成、生成未同步、同步未重命名、重命名未提交、提交后响应丢失等窗口。
- 实现终态、借用输入关闭、`inputs_released` 及内部输入引用释放的一致收尾；先覆盖正常完成和明确失败路径。

验收：共享卷提交 probe 得到真实报告文件；ready 前无 API 可消费引用；文件和元数据不一致不返回成功；终态重试不替换 artifact ID；注入发布阶段崩溃后可安全完成提交或定向回收。至少跑通一次真实容器重启。

### P4：补齐操作、DAG 和部分成功

工作内容：

- 实现视频转码、音频转码、视频音轨转换、按时间抽帧和静态图片缩放，统一复用执行器、预算、发布及错误接口。
- 实现操作/预设版本冻结、启动能力检查及实际引擎/镜像版本记录。
- 实现按拓扑顺序的步骤执行、上游产物内部引用、独立分支继续、失败依赖跳过和声明输出终态计算。
- 实现抽帧逐项结果与集合清单：实际媒体 PTS、重复和无序请求、越界错误、部分成功。完成的部分集合不可补写，全部失败不伪造可用集合。
- 实现 Pillow 独立子进程的静态图片处理、方向和透明语义、动画/多页及像素限制；移除不需要的图片元数据。

验收：六个操作均用真实引擎验证；音频采样率/声道、视频尺寸/帧率/编码和图片方向符合预设。抽帧命中以已知帧时间验证，不以输出文件名或帧数猜测；损坏输入、无音轨和不支持格式有稳定错误。组合任务的每个声明输出能对应成功、失败或跳过结果，独立分支不会被误取消。

### P5：取消、恢复、租约与回收

工作内容：

- 实现幂等取消接口，持久化意图先于停止操作；终态不再改写。取消期间已发布输出仍可用，未发布结果不得被消费。
- 完成容器生命周期和恢复路径：旧执行者停止确认、尝试提交资格撤销、已提交步骤复用、固定副本复用、取消优先和恢复次数上限。
- 实现显式租约申请/续期/释放、保留期延长与提前 release。统一 ready/retiring/deleting 状态，拒绝 retiring 后的新引用和续租，保留原有效引用的读取能力。
- 实现已有 artifact 作为输入时的原子引用获取，覆盖排队与恢复；已发布中间结果也需受内部引用保护。
- 实现定向回收工作目录、下载副本、到期产物、失效租约及发布残留。清理失败可以重试，不提前删除授权元数据，不递归清理输入卷。
- 实现终态后至少 24 小时的短期幂等与最小任务记录，以及不再需要的来源秘密提前清除。无有效产物/引用且保证窗口结束后清除最小任务；不建立长期历史库。

验收：

- 领取、取消、完成并发竞争结果唯一；请求取消后若进程尚未停止，状态不能提前显示输入释放。
- 容器硬停止/重启后取消意图不丢失，已发布绑定不变，不兼容或丢失输入明确失败；不能仅按租约到期推断进程死亡。
- 申请/续期/引用获取与回收竞争不产生成功但已失效的引用。下游排队时原产物即使到期仍受保护，新的下游引用被拒绝。
- 两个并发任务中取消一个不影响另一个；不同任务暂存、输出和清理互不混用。
- 幂等有效期内重放仍返回可查询任务；保证窗口和引用都结束后任务可为 `404`，共享源文件始终保留。

### P6：HTTP 来源与产物消费

工作内容：

- 实现 GET 来源获取、敏感头受限保存、实际字节/摘要校验、连接/闲置/总时限以及有限退避重试。排队消耗的时间纳入总预算，不假定签名 URL 支持 HEAD。
- 实现 URL 来源规则、实际连接 DNS 结果验证、有限重定向逐跳校验、跨源认证头剥离、环境代理禁用及媒体内部网络引用阻断。
- 实现一次成功获取后的固定副本与持久检查点；步骤和恢复复用副本，不因重试再次读取变化 URL。失败的未固定下载可按预算从头获取。
- 实现单文件/集合成员内容、分页清单和元数据访问，明确对 retiring 产物携带有效租约的访问方式。
- 实现 HEAD、单 Range、ETag/If-Range、非法范围及合法多 Range 回退；响应引用覆盖实际发送、断开、超时和 finally，发送停止后才释放。
- 绑定公网/内网可达基址、调用方授权和 HTTPS 入口约定，避免返回只有容器内部可解析的 URL。

验收：受控 HTTP 测试服务模拟重定向、DNS 变化、跨源凭据、闲置、慢传输、断流及校验失败。验证限额按实际字节生效；固定副本生成后来源修改不改变同一任务的结果；流未结束时即使产物到期也不能删除，断开后最终释放读取引用。网络测试不依赖真实账号、OSS 凭据或长期可用的外网链接。

### P7：部署、故障与容量验收

工作内容：

- 交付单服务 Compose 示例，含私有 state/work、共享输入输出、非 root 权限、init、重启、CPU/内存/PID 限制、磁盘预算和健康检查。状态库只在本容器持久卷中，无数据库 sidecar。
- 交付同 Compose 与跨 Compose 的 external volume/network 示例，明确业务输入读写、服务输入只读、服务输出读写、业务输出只读；不依赖两边挂载路径相同。
- 在两台真实宿主机完成 HTTP 来源、提交、查询、下载及结果校验；若暂缺第二台机器，登记为未验证，不用同机容器替代通过证据。
- 在目标机器分别运行 Worker=1、2、4 的有界并发试验，记录吞吐、排队、取消延迟、API 响应、峰值 RSS、CPU 和临时磁盘。按实测推荐默认并发，不宣称 4 个槽在所有机器都合适。
- 注入数据库繁忙/失败、磁盘不足、媒体子进程卡住、应用退出、容器硬停止、发布中断、读取断连、回收竞争；确认没有接受后丢任务、提前输入释放或跨任务误删。
- 整理 OpenAPI 用法、三种调用示例、输入交接、租约读取、幂等窗口、配置、故障定位、状态备份/迁移、版本升级排空及 fixture 使用说明。

验收：Ruff、pyright、单元测试、真实媒体本地集成、容器生命周期测试和三种部署验证均留有结果。失败及未验证项逐项登记，不把某一层通过扩张为整体可部署结论。

| `ffmpeg_h264_640x360.mkv` | 62,835 | Matroska，H.264/AAC，640×360，24fps，约 1.023 秒 | 非 MP4 容器、探测与容器转换 |

三个 `ffmpeg_*` 样例由 `testsrc2 + sine` 合成，原目录 README 保留生成命令。复制时将相关来源和命令写入目标 fixture README，并记录六个文件的 SHA-256；复制后核对摘要，保留可追溯来源。测试可使用相对仓库根目录寻址，确保单独克隆 `ffmpeg-agent` 后即可运行。

复制清单不包含 PDF、DOCX 和 `workshop_recordings/`。后者是真实会议录音，原说明限定为内部 ASR 回归，且不属于六项媒体操作的必要基础样例。现有媒体的公开再分发许可未在目录说明中确认，因此本计划记录的是用户授权的内部测试复用，不将其写成开放素材授权。

### 4.2 需补充的确定性样例

以下在目标仓库测试临时目录生成，或以小型脱敏 fixture 保存生成脚本和摘要，不能靠现有六个样例推断边界已覆盖：

- 已知帧 PTS 的短视频：请求 0、帧间点、最后一帧、等于/超过末尾时间，检查第一帧不早于请求点；重复和无序请求检查逐项映射。
- 非零起始时间、可变帧率、旋转元数据、非方形像素及奇数尺寸，验证时间/画面归一化和拒绝边界。
- 无音轨视频、多音轨视频、零字节、截断与损坏媒体，验证轨道选择、失败和独立分支继续。
- 带 EXIF 方向的 JPEG、透明 PNG、静态/动画 WebP、多帧图片、超限像素和不支持颜色空间，验证图片处理范围。
- 含本地或网络外部引用的媒体、路径替换与符号链接样例，验证解析和文件边界。
- 长任务、大输入和临时磁盘压力按需生成，放在资源测试层；普通单测不携带或生成大文件。
- HTTP 状态、断流、重定向和地址变化由受控测试服务器模拟；来源文件仍可用复制后的基础媒体。

## 5. 验证分层与证据

| 层次 | 验证内容 | 不得替代的证据 |
| --- | --- | --- |
| 单元与协议测试 | schema、DAG、状态转换、配额、幂等、时间/租约规则 | 不能证明真实媒体格式正确或子进程已停止 |
| 真实本地集成 | 临时 SQLite、真实 FFmpeg/ffprobe/Pillow、独立临时目录 | 不能证明容器终止和跨机网络行为 |
| 故障与并发测试 | 事务取消、领取/取消竞争、发布中断、读取/GC 竞争、Worker 1/2/4 | 不能仅用 sleep 或状态字段推断文件安全 |
| 容器端到端 | 单实例、权限、信号、强停恢复、挂载和限制 | 不以本机 Python 进程重启替代容器强停 |
| 三种部署验收 | 同 Compose、跨 Compose 同 daemon、真实两宿主机 HTTP | 不用同机两个容器宣称跨宿主机通过 |

结果应记录命令、退出码、镜像/依赖/引擎版本、架构和关键断言。媒体验证优先检查规范化元数据、解码结果和已知时间语义，不跨引擎构建比较完整压缩文件的逐字节一致性。摘要用于输入复制和产物完整性，不作为跨版本编码确定性承诺。

状态和生命周期测试使用独立临时状态目录；涉及文件清理时只操作本用例登记的 job/attempt/artifact，不清空真实数据库、全卷或调用方输入。HTTP 测试服务默认只绑定测试可达接口，认证测试使用专门的无业务权限测试凭据。

## 6. 并行分工与实施约束

- 共享合同 owner 负责 schema、状态机、SQLite 数据访问、尝试/引用接口以及最终集成；其他模块通过确定接口工作，不直接新开数据库连接。
- 媒体操作 owner 可在 P3 后负责 P4 的操作适配、预设和真实媒体测试；生命周期 owner 同期负责 P5 的租约、取消、恢复和清理。并行前明确文件归属和必要的接口变更协调。
- HTTP owner 在 P5 读取引用接口稳定后接入 P6；部署与验证 owner 可提前整理 fixture、验收矩阵及文档，但不把占位内容算作验证通过。
- 每阶段完成后先跑直接相关验证；只有新增行为或失败需要时扩大检查。不要因为计划存在八个阶段就为局部修改机械引入额外流程。

初次实施可按 P0～P3 先形成可运行里程碑，然后补齐 P4～P7；该里程碑不代表首版全部完成。Git commit、push、tag 和对外发布按届时用户授权执行，本计划本身不授权远端发布。
